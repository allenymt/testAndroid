- APP 识别结果：符合 NTAG 424 DNA 的 GetVersion 特征。
- RF UID 与 GetVersion UID 一致，当前未观察到 Random ID。

二、NDEF 文件 02 当前设置

- GetFileSettings 命令：90 F5 00 00 01 02 00
- 原始响应：00 00 E0 EE 00 01 00 91 00
- FileType：StandardData File（00）
- FileOption：Plain communication，SDM disabled（00）
- FileSize：256 bytes（00 01 00，小端）
- AccessRights 在线路上按低字节在前编码：E0 EE -> 逻辑值 EE E0
  - Read：Free（E）
  - Write：Free（E）
  - ReadWrite：Free（E）
  - Change：Key 0（0）

结论：当前 NDEF 文件可以匿名读取和写入，但修改文件设置（包括开启 SDM）必须先使用 Key 0 完成认证。

三、当前 NDEF 内容

- NLEN：00 CE（206 bytes）
- NDEF records：2
- URI host：wdb-applink.weidian.com
- Android Application Record：com.koudai.weidian.buyer
- 当前 URL 是静态 NDEF 内容，没有 SDM PICCData、ReadCounter 或 SDMMAC 占位字段。

- Read_Sig 命令：90 3C 00 00 01 00 00

- NXP AN12196 的 Read_Sig 示例同样使用 91 90 作为响应结尾。APP 已兼容该实卡行为。
- 当前 Demo 仅读取签名，尚未使用 NXP 公钥执行 ECDSA secp224r1 验签。

五、APP 开启 SDM 的可行性判断

技术上可以通过 Android APP 开启；当前 Demo 已增加仅面向本测试卡的受控写卡入口。开启条件如下：

1. 必须掌握当前卡片正确的 AppMasterKey（Key 0）。TagInfo 显示“Default AppMasterKey”不能单独证明 Key 0 一定仍是 16-byte 全零值；应以供应商或个性化记录为准，禁止盲目重试未知密钥。
2. APP 需要实现 AuthenticateEV2First（或卡片当前模式对应的认证）以及 Full Secure Messaging，包括会话 ENC/MAC 密钥、TI 和命令计数器处理。
3. 先把 NDEF 改成 SDM URL 模板，为 PICCData、SDMMAC 等动态字段预留固定长度占位符，并按最终 NDEF 字节计算 PICCDataOffset、SDMMACInputOffset 和 SDMMACOffset。
4. 通过受 Full Secure Messaging 保护的 ChangeFileSettings 为 File 02 设置 FileOption、AccessRights、SDMOptions、SDMAccessRights 和各字段 offset。不能使用一条未认证的明文 ChangeFileSettings 开启。
5. 必须预先确定 SDMMetaReadKey、SDMFileReadKey 和 SDMCtrRet 对应的 AppKey，并替换所有仍为出厂全零值的应用密钥。生产密钥不能硬编码进 APK。
6. 开启后应立即重新读取 GetFileSettings 和 NDEF，并由后端/HSM 验证 SDMMAC、解密 UID/ReadCounter、原子记录计数器以防重放。

建议：这张测试卡可用于受控环境中的 SDM 个性化 Demo；正式产品应由发卡工具、SAM 或后端/HSM 管理 Key 0 和每卡多样化密钥，APP 只负责读卡和转交动态数据。

- NDEF URL 模板：https://wdb-applink.weidian.com/ntag424?e=<32 个十六进制字符>&c=<16 个十六进制字符>
